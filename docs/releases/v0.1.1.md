# v0.1.1

Second release of tableprims. It adds a capability interface to both
implementations and gives the binary64 facts of exact numbers in Go as well
as Rust. The conversion, the documents it reads and writes, and the
conformance to the Tabular Exchange Standard, contract revision
`tabular-exchange/0.1.0`, are unchanged from v0.1.0.

## What it adds

- **Capabilities.** Every implementation surface reports the capabilities
  it implements, from six identifiers: `read-schema`, `read-policy`,
  `read-rows`, `quantize`, `binary64-decision` and `xlsx-write`. Asking for
  one it lacks is an explicit error, `unsupported`, and an identifier that
  names none is `unknown`; neither is a refusal of the standard. Go:
  `table.Capabilities`, `table.Require`, `*table.CapabilityError`. Rust:
  `tableprims::capabilities`, `tableprims::require`,
  `tableprims_xlsx::capabilities` and `tableprims_xlsx::require`. See
  [docs/capabilities.md](../capabilities.md).
- **Binary64 facts.** For an integer or a decimal, both implementations give
  the nearest binary64 value, ties to even, and two independent facts:
  whether the value is exact, and whether its shortest decimal spelling
  denotes the number. The integer 2^60 is exact but does not round-trip; the
  decimal 0.1 round-trips but is not exact. Go: `Integer.Binary64`,
  `Decimal.Binary64`. Rust: `binary64::integer_facts`,
  `binary64::decimal_facts`. See [docs/binary64.md](../binary64.md).
- **The XLSX rule in Go.** `table.XLSXWriteR1Binary64FromInteger` and
  `table.XLSXWriteR1Binary64FromDecimal` give the eligibility of a number
  for a number cell under the `xlsx-write/r1` profile, with the same reason
  codes and texts as Rust. The Go package still writes no workbook.
  `binary64-decision` is no longer a Rust-only capability.

The Rust functions `binary64::from_integer` and `binary64::from_decimal`
keep their signatures, reasons, order of reasons and verdicts.

## Conformance

Both implementations still meet the expectation of each of the 477 vectors
and fixtures of the standard that they run. Two suites owned by this
repository, apart from the standard, are new: the capability suite
(`conformance/capabilities/v0`) and 63 binary64 cases
(`conformance/binary64/v0`) whose expectations are derived independently
with CPython. Both implementations run all 63 binary64 cases; each surface
runs the capability cases for its own report. Both suites require a
disagreement when any expectation is altered.

CI runs both on Linux x86_64 and aarch64, macOS arm64 and Windows x86_64 and
aarch64, with Rust 1.88.0 and Go 1.26.10.

## Install

- Go: `go get github.com/fulmenhq/tableprims@v0.1.1`
- Rust: the crates are not published to a registry; depend on this
  repository at the tag `v0.1.1`, or build `tablebolt` from source with
  `cargo build --release -p tableprims-cli`.

No binary or package artifact is published with this release.
